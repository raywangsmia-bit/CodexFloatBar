# CodexFloatingBar Go 原生壳实施路线

Wails P0 因 WebView2 空闲总工作集约 335 MiB 未通过。替代路线不再更换前端框架，
而是从正式运行时彻底移除浏览器内核。

## 架构决定

| 部分 | 技术 | 是否进入正式运行时 |
| --- | --- | --- |
| UI 设计和场景预览 | 纯 HTML、CSS、JavaScript | 否 |
| 设计导出 | 开发模式 Go HTTP 服务 + 系统 Edge | 否 |
| UI 包 | JSON manifest + 多 DPI PNG | 是 |
| 桌面壳 | Go + Win32 + `UpdateLayeredWindow` | 是 |
| 数据服务 | Go 标准库为主 | P2 接入 |

React、Vite、Node、Wails、WebView2 和 .NET 均不再是正式运行依赖。HTML 是设计
源；导出的 manifest 是窗口尺寸、DPI 资源和点击区域的唯一权威来源。

按用户明确要求，本轮不再执行窗口压力测试和 5 分钟空闲性能回归；最终多窗口构建
没有重跑 200/50 次循环或 5 分钟采样。已有较早的主窗口数据仅保留作历史参考，不
作为当前 Beta 的性能验收结果。WPF 仍是正式版本，原生候选使用独立应用 ID、
互斥体、配置和可执行文件名。

## 无需编译的 UI 流程

```text
修改 HTML/CSS
  -> 静态指纹变化并整页刷新
  -> 点击导出
  -> 浏览器计算最终布局和 data-action 命中区
  -> Edge 导出十四个 surface × 四档 DPI，共 56 张 PNG
  -> 新 generation 全部验证通过
  -> manifest 最后原子切换
  -> Go 三窗口一致热加载
```

任意 HTML/CSS 不能无损转换为通用原生控件。本项目使用固定尺寸的最终栅格图，
以换取浏览器预览与正式窗口的像素一致性；动态数据采用受限的文字、进度、42 格
热图和原生统计图层，不在正式程序中实现 CSS 引擎。最终 bundle 指纹为
`codexfloatingbar-4d5a9b6f7d18`，generation 为 `67875f0ef1300d7a`。

## 下一步实施路线

### P2：Go 数据服务（已实现）

- 已制作脱敏 session JSONL、配置、认证声明和损坏缓存 fixture。
- 已用链接现有 WPF 服务源码的 C# oracle 对比模型、推理强度、速率、额度和 Token
  聚合结果，并用源码/fixture 指纹防止 golden 陈旧。
- Go 只在进程内传递安全 snapshot，不把 JWT、`auth.json` 或原始日志交给 UI 层。
- 已实现 mtime 轮询、刷新合并和取消，不增加文件监听依赖。
- 已将动态值渲染到受限文字、进度和 42 格热图层，继续保持无 WebView 运行时。
